## 1. 정체 — ReviewFlag 의 확장판

지금 `ReviewFlag`는 섹션 옆 "복습에 추가" 별표(id `chN-sM`)만 한다. 이 기능은 그 자리에
**① 내 메모 텍스트 ② 그 항목에 대한 질문(AI/사람 답변)**을 더하고, **동료의 메모/질문도 함께 보이게** 한다.
즉 "복습 플래그"가 "**항목별 협업 주석**"으로 확장된다.

재사용 조각:
- **`ReviewFlag`** → 앵커·배치 패턴
- **Supabase 동기화(P0~P2 완료분)** → 저장·기기간
- **`TutorChat`(로컬 Ollama)** → AI 질의
- **`@series/store`·`AuthPanel`·RLS** → 인증·본인 검증

---

## 2. 이 방향이 만든 3대 난관 (정직하게)

1. **임의 항목 ID — 가장 큰 작업(콘텐츠).** 개념카드·문제·수식마다 **안정적 ID**가 있어야 메모를
   붙인다. 섹션 앵커(ReviewFlag)조차 **part1~5에만 있고 6~11은 0개**(통합검색 작업에서 확인).
   자동 위치기반 ID(예: N번째 개념카드)는 콘텐츠 편집 시 어긋나 메모가 엉뚱한 항목에 붙는다.
   → 129챕터 전 요소에 ID를 심는 콘텐츠 패스가 선행돼야 안정적.
2. **공유 → 모더레이션·신원·볼륨.** 남의 눈에 보이니: 작성자 표시(이름/이메일), 본인만 수정·삭제,
   관리자 삭제/신고, 한 항목에 메모 여러 개일 때 스레드·접기·정렬. 사내(신원 기반)라 리스크는 낮음.
3. **사람 Q&A → 답변·큐·알림·관리자.** 질문 상태(열림/해결), 강사 답변, 미해결 큐, 알림. 개인 메모와
   저장·공개 모델이 다르다.

## 3. 에토스 주의

- **주석은 로그인 필요** — 공유 열람·작성 모두. "즉시 체험(무로그인)"과 분리된 **옵트인 소셜 층**.
- **서버 저장·동료 가시** — 개인 메모(진도처럼 사적)와 달리 남이 본다. 사내 도입 맥락에선 수용 가능하나
  "누가 무엇을 썼나"가 노출됨을 명시. 익명 옵션은 별도 결정.
- 비용 0·유출 최소 원칙: 여전히 메타·텍스트만. AI 답변은 로컬 Ollama라 외부 유출 없음.

## 4. 데이터 모델 (Supabase)

```sql
-- 항목별 주석 (메모 + 질문 통합). 공유: 로그인 전원 읽기, 본인만 쓰기/수정/삭제(+관리자 삭제).
create table annotations (
  id           uuid primary key default gen_random_uuid(),
  user_id      uuid not null references auth.users on delete cascade,
  author_name  text not null,               -- 표시용(이메일 앞부분 등) — 공유라 필요
  part         smallint not null,
  chapter      text not null,               -- 'ch6'
  item_id      text not null,               -- 앵커 id (예: 'ch6-s2', 'ch6-concept-qkv')
  kind         text not null default 'note',-- 'note' | 'question'
  body         text not null,
  ai_answer    text,                        -- AI 답변(질문일 때, 선택)
  resolved     boolean not null default false,
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now()
);

-- 질문에 대한 사람(강사) 답변 — 스레드
create table annotation_answers (
  id            uuid primary key default gen_random_uuid(),
  annotation_id uuid not null references annotations on delete cascade,
  user_id       uuid not null references auth.users on delete cascade,
  author_name   text not null,
  body          text not null,
  created_at    timestamptz not null default now()
);

-- RLS: 읽기=로그인 전원(공유), 쓰기=본인. (관리자 삭제/답변 정책은 §7 참고)
alter table annotations enable row level security;
alter table annotation_answers enable row level security;
create policy read_all  on annotations for select to authenticated using (true);
create policy write_own on annotations for insert to authenticated with check (auth.uid() = user_id);
create policy edit_own  on annotations for update to authenticated using (auth.uid() = user_id) with check (auth.uid() = user_id);
create policy del_own   on annotations for delete to authenticated using (auth.uid() = user_id);
create policy read_all_a  on annotation_answers for select to authenticated using (true);
create policy write_own_a on annotation_answers for insert to authenticated with check (auth.uid() = user_id);
create policy del_own_a   on annotation_answers for delete to authenticated using (auth.uid() = user_id);
```
- **인덱스**: `(part, chapter, item_id)` — 항목별 조회. `(kind, resolved)` — 미해결 질문 큐.
- 관리자 삭제: 정책에 관리자 이메일 화이트리스트 `or` 추가(§7). 지금은 본인 삭제만.

## 5. 컴포넌트·모듈 (재사용 위치)

- **`packages/ui`**
  - `NoteMarker.vue` — 항목 옆 아이콘 + **개수 배지**(그 항목 주석 수). 클릭 → 패널 토글.
  - `NotePanel.vue` — 팝오버/사이드: 그 항목의 메모·질문 **스레드**(작성자·시각) + 작성 폼 +
    "🤖 AI에게 묻기" + (질문이면) 답변 목록 + (강사) 답변 작성. 자체 완결 scoped 스타일(AuthPanel 방식).
  - 항목 래핑: `ConceptCard`·`Quiz`·`StepQuiz`·`MathBlock`에 **`anchorId` prop**(선택) → 있으면 NoteMarker 렌더.
- **`@series/store`** (sync.ts 확장 또는 신규 `annotations.ts`)
  - `fetchAnnotations(part, chapter)` / `postAnnotation(...)` / `updateAnnotation` / `deleteAnnotation`
  - `postAnswer(annotationId, body)` / `fetchOpenQuestions()`(관리자)
  - 선택: Supabase **Realtime** 구독으로 항목 열었을 때 실시간 갱신.
- **AI**: `NotePanel`의 "AI에게 묻기" → 항목 맥락(chapter/item 텍스트) + 질문을 `TutorChat`에 프리필
  (기존 `open-search` 같은 커스텀 이벤트로 열기). 답변을 `ai_answer`에 저장(선택).
- **뷰**: 포털 또는 각 부에 "내 메모/질문" 목록 + 관리자 "미해결 질문" 큐(`/adoption` 옆).

## 6. 항목 앵커(item_id) 방침 — 핵심

- **1차(섹션 단위)**: 기존 `ReviewFlag` 앵커(`chN-sM`) 재사용 → part1~5 즉시. part6~11은 앵커 백필.
- **2차(임의 항목)**: 공용 컴포넌트에 `anchorId` prop 부여, 콘텐츠가 명시적 ID를 넘긴다
  (예: `<ConceptCard anchorId="ch6-attention" …>`). **자동 인덱스 ID는 금지**(편집 시 메모 오정렬).
- ID 네이밍 규칙 정본화: `{chapter}-{type}-{slug}` (예: `ch6-concept-qkv`, `ch6-quiz-3`).
- 이 콘텐츠 패스가 **가장 큰 비용** — 통합검색 §4 3단계(앵커 정비)와 같은 성격. 별도 트랙으로 관리.

## 7. 관리자·모더레이션 (사람 Q&A)

- **관리자 판별**: env `VITE_ADMIN_EMAILS`(콤마 구분) 또는 RPC 내 화이트리스트. `isAdmin` = 이메일 일치.
- **강사 답변**: 관리자만 `annotation_answers` 작성 + `annotations.resolved=true` 토글.
- **관리자 삭제**: RLS 정책에 `or (auth.jwt()->>'email') = any(admin_list)` 추가(스팸 제거).
- **미해결 큐**: `select ... where kind='question' and resolved=false` (관리자 뷰). 알림은 P3 후반(선택).

## 8. 단계 롤아웃

| 단계 | 내용 | 규모 | 메일/콘솔 |
|---|---|---|---|
| **P0 앵커 기반** | 공용 컴포넌트 `anchorId` prop + part6~11 앵커 백필 + ID 네이밍 정본 | **큼(콘텐츠)** | 코드 |
| **P1 공유 메모** | `annotations` 테이블·RLS + store + `NoteMarker`/`NotePanel`, 작성자 표시·본인 수정/삭제 | 중 | schema 실행 |

| **P3 사람 Q&A + 관리자** | `annotation_answers`·미해결 큐·강사 답변 UI·모더레이션·(선택)알림 | 중~큼 | 관리자 지정 |

> **권장 시작 순서**: P0 전면(전 콘텐츠 ID)에 바로 들어가지 말고, **part1 섹션 단위로 P1+P2를 얇게 관통**
> (기존 ReviewFlag 앵커 재사용) → 공유 메모+AI 질문이 쓸 만한지·볼륨·모더레이션 감을 검증 → 그 뒤 P0(임의
> 항목 ID)·P3(사람 Q&A)에 투자. (백엔드도 part1 검증 후 12부 전파한 방식과 동일.)

## 9. 검증 계획

- P1: 로그인 두 계정 → A가 항목에 메모 → **B가 같은 항목에서 A의 메모를 봄**(공유·RLS). 본인만 수정/삭제.
- P2: "AI에게 묻기" → TutorChat이 항목 맥락으로 답 → `ai_answer` 저장·표시.
- P3: 일반 유저 질문 → 관리자 큐에 뜸 → 관리자 답변 → 질문자 화면에 답 표시·resolved.
- 실 Supabase headless E2E(기존 방식) + 조립 배포본 확인.
