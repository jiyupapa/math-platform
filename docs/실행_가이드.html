1절

실행 방식 세 가지

온톨로지 기능을 전부 보려면 방식 A가 답입니다. 다른 두 방식은 목적이 다릅니다.

A. 조립본 추천12개 앱을 빌드해 한 주소 아래 묶어 띄웁니다. 진도 겹치기, 부 간 링크, 복습 경로까지 전부 동작합니다.http://localhost:4173
B. 개발 서버한 부만 빠르게 띄웁니다. 코드를 고치면 즉시 반영됩니다. 다른 부로 가는 링크와 진도 겹치기는 안 됩니다.http://localhost:5173
C. 노트북웹 챕터와 1:1인 Jupyter 노트북과, 웹과 같은 개념 카드를 쓰는 노트북 튜터입니다.jupyter lab

AI 튜터(Ollama)와 백엔드(Supabase)는 세 방식 어디에나 선택적으로 붙습니다. 둘 다 없어도 나머지는 전부 돕니다.

3절

최초 1회 설치

1
저장소 받기 
git clone https://github.com/jiyupapa/math-platform.git
cd math-platform

이미 폴더가 있으면 그 폴더로 이동만 하면 됩니다. 예: cd C:\STUDY\MATH_PLATFORM

2
의존성 설치 
npm install

12개 앱과 공용 패키지를 한 번에 연결합니다. 끝나면 설치 후 스크립트가 온톨로지 산출물 두 개를 자동으로 만듭니다. 이 두 줄이 보이면 성공입니다.

# npm install 끝부분에 나와야 하는 줄
✅ 통합검색 인덱스: 챕터 129 + 개념 375 = 504 항목 → 12개 앱 public/ 에 기록
✅ 개념 그래프: 개념 114 · 장 129 → 12개 앱 public/concept-graph.json

안 보이면 직접 만듭니다: npm run search:index 와 npm run ontology:graph. 이 파일들은 git에 들어가지 않으며 언제든 다시 생성됩니다.

3
노트북 환경 (방식 C를 쓸 때만) 
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m ipykernel install --user --name math-platform --display-name "Python (MATH_PLATFORM)"

루트에 venv 하나만 만듭니다. 11개 부의 노트북이 전부 이 커널 하나로 돕니다. Mac·Linux는 .venv/bin/python 입니다.

4
AI 튜터 모델 (선택) 
ollama pull gemma4:e2b

기본 모델입니다. 없으면 설치된 다른 채팅 모델을 튜터 창의 드롭다운에서 고를 수 있습니다. 자세한 것은 7절.

4절

방식 A. 조립본으로 전부 띄우기

포털이 각 부의 진도를 읽고, 챕터 띠가 다른 부로 연결되고, 복습 경로가 계산되는 것은 열두 앱이 한 주소 아래 있을 때뿐입니다. 그래서 온톨로지 확인은 이 방식으로 합니다.

1
빌드해서 조립하기 (약 3분) 
npm run deploy:build

순서대로 이렇게 돕니다. 온톨로지 검사 → 검색 인덱스와 개념 그래프 생성 → 12개 앱 빌드 → deploy/ 폴더로 조립. 검사가 실패하면 여기서 멈추고 이유를 출력합니다.

2
띄우기 
npm run deploy:serve

브라우저에서 http://localhost:4173 을 엽니다. 포털이 /, 각 부가 /part1/ … /part11/ 입니다. 끌 때는 Ctrl+C.

한 줄로 하고 싶다면

Windows는 start.cmd all, Mac·Linux·Git Bash는 ./start.sh all. 위 두 명령을 이어서 실행해 줍니다. 인자 없이 실행하면 메뉴가 뜹니다.

Git Bash에서 빌드 명령에 --base=/ 를 손으로 붙이지 마세요

Git Bash가 / 로 시작하는 인자를 Windows 경로로 바꿔 버려 빈 화면이 나옵니다. npm run deploy:build 는 그 문제를 겪지 않습니다. 꼭 손으로 돌려야 하면 앞에 MSYS_NO_PATHCONV=1 을 붙입니다.

5절

온톨로지 확인 체크리스트

조립본이 떠 있는 상태(4173)에서 위에서 아래로 따라가면 10분입니다. 튜터 항목만 Ollama가 필요합니다.

#무엇을어디서이렇게 보여야 정상
1검색의 이웃 줄아무 화면에서 Ctrl+K, 조련 입력6부 결과 아래에 "이 과정에서는 '조련'(6부) · 밖에서는 fine-tuning" 같은 줄이 붙습니다. KL 발산을 치면 5부 5장이 회수처보다 먼저 옵니다.
2챕터 띠/part5/ch/ch5 상단"이 장에서 처음 배우는 개념 KL 발산 · 먼저 알아 두면 크로스 엔트로피(5부 4장) · 다음에 다시 만나는 곳 6부 6장 …". 다른 부 링크는 새 탭으로 열립니다.
3개념 지도/concepts?c=kl-divergenceKL 발산이 선택된 채 열리고, 먼저 알아야 하는 사슬은 실선, 그 개념을 쓰는 다음 개념은 점선으로 이어집니다. 아래 상세 패널에 배우는 곳과 다시 쓰이는 곳.
4비유어 사전/glossary부별 표 65행. '목줄' → KL 발산, '보폭' → 학습률처럼 비유어와 실무 용어가 짝지어져 있고 검색창으로 거를 수 있습니다.
5튜터의 부 간 안내 Ollama/part1/ch/ch2 오른쪽 아래 🤖"KL 발산은 어디서 배워요?"에 5부 5장과 먼저 볼 개념을 답합니다. 1부 튜터인데 5부를 안내하는 것이 핵심입니다.
6다시 볼 개념/diagnose 12문항, 몇 개는 일부러 틀리기제출 뒤 포털 홈에 "진단을 개념으로 보면 · 다시 볼 개념: 연쇄법칙(2부 6장) …" 카드가 뜨고, 개념 지도에서 그 개념에 주황 테두리가 붙습니다.
7복습 경로아무 챕터의 소제목 옆 ☆ 복습에 추가를 두세 곳 누른 뒤 포털 홈"복습 경로" 카드에 ★표시한 개념부터 선수 개념까지 화살표 순서로 이어집니다. 완료한 장의 개념은 ✓.
8가르치는 절/part7/ch/ch8#ch8-s4 · /part11/ch/ch37부 8장 4절이 지식 그래프와 GraphRAG를 설명하며 "이 사이트의 튜터가 바로 이 방식"이라고 짚고, 11부 3장 끝에 "도구 스키마는 작은 온톨로지" 카드가 있습니다.
9질문 집계 백엔드/adoption (로그인)동료들이 챕터에 남긴 메모·질문이 개념별로 묶인 표. Supabase 설정과 로그인이 있을 때만 채워집니다(9절).
왜 어떤 것은 개발 서버에서 안 보이나

브라우저는 주소(포트)마다 저장소를 따로 둡니다. 방식 B는 부마다 포트가 달라 포털이 다른 부의 진도·표시를 읽을 수 없고, 다른 부로 가는 링크는 글자로만 표시됩니다. 그 부 안에서의 띠·검색·튜터·개념 지도는 방식 B에서도 정상입니다.

방식 B. 한 부만 개발 서버로

챕터나 컴포넌트를 고치면서 바로 보고 싶을 때 씁니다. 저장하면 화면이 즉시 바뀝니다.

# 5부(정보이론)만
npm run dev -w apps/part5/web
# 포털만 (개념 지도 · 비유어 사전 · 진단 확인 가능, 진도 겹치기는 불가)

7절

AI 튜터 (Ollama)

튜터는 각자 PC의 Ollama에 붙습니다. 서버도 계정도 비용도 없고, 질문이 PC 밖으로 나가지 않습니다.

1
설치와 실행

ollama.com에서 설치합니다. Windows·Mac은 앱을 켜 두면 서버가 돌고, 터미널에서는 ollama serve 로도 켤 수 있습니다.

2
모델 받기 
ollama pull gemma4:e2b      # 기본 모델, 작고 빠름
ollama pull gemma3:4b       # 조금 더 크고 답이 안정적, 선택

튜터 창의 드롭다운에 설치된 채팅 모델이 전부 뜨므로 아무거나 골라도 됩니다. 임베딩 전용 모델은 목록에서 제외됩니다.

3
동작 확인 
curl http://localhost:11434/api/tags

모델 목록이 JSON으로 오면 준비된 것입니다. 첫 질문은 모델을 메모리에 올리느라 수십 초 걸리고, 그 뒤 15분간은 바로 답합니다. 시연 전에는 한 번 미리 물어 두세요.

튜터가 다른 부 개념을 아는 원리

질문에 나온 개념을 개념 그래프에서 찾아 카드(배우는 곳, 먼저 알아야 하는 개념, 다시 쓰이는 곳, 비유어)를 최대 세 장 시스템 프롬프트에 덧붙입니다. 카드 한 장이 약 100토큰이라 작은 모델에도 부담이 없습니다. 카드가 없으면 예전처럼 "이 과정에 없다"고 답하므로, 그렇게 답하면 12절을 보세요.

다른 PC의 Ollama를 쓰려면 빌드 전에 루트 .env 에 VITE_OLLAMA_URL=http://10.0.0.5:11434 처럼 적습니다. 빌드 시점에 값이 박히므로 바꾼 뒤에는 다시 빌드해야 하고, 그 서버는 CORS를 허용해야 합니다.

8절

방식 C. 노트북과 노트북 튜터

1
Jupyter 띄우기 
.venv\Scripts\python.exe -m jupyter lab

저장소 루트에서 실행하면 브라우저에 JupyterLab이 열립니다. apps/part1/notebooks/ 처럼 부 폴더로 들어가 노트북을 엽니다. 커널은 Kernel → Change Kernel → Python (MATH_PLATFORM).

2
노트북 튜터에게 다른 부 개념 묻기 
# 1부 노트북의 아무 셀에서
from tutor import ask
ask('KL 발산은 어디서 배워요?', chapter='ch2')
# → "5부 5장에서 배우게 됩니다. 먼저 크로스 엔트로피(5부 4장)…"  (Ollama 필요)

# 채팅창으로 쓰려면
from tutor import chat
chat('ch2')

웹 튜터와 같은 개념 카드를 파이썬으로 옮긴 것이라 답이 같은 방식으로 나옵니다. 각 부 web/public/concept-graph.json 을 읽으므로 npm install 이 먼저 되어 있어야 합니다.

3
Ollama 없이 카드 매칭만 확인 
cd apps\part1\notebooks
..\..\..\.venv\Scripts\python.exe -c "from tutor import match_concepts; print([c['id'] for c in match_concepts('KL 발산은 어디서 배워요?')])"
# → ['kl-divergence']
4
노트북이 깨지지 않았는지 검증 (선택) 
.venv\Scripts\python.exe -m jupyter nbconvert --to notebook --execute --stdout --ExecutePreprocessor.kernel_name=math-platform apps\part7\notebooks\ch08_rag_assembly.ipynb

7부 8장 노트북에는 지식 그래프 두 걸음 걷기 실험이 들어 있습니다. 에러 없이 끝나면 통과입니다.

9절

백엔드 (Supabase, 선택)

백엔드가 없어도 진도·복습·진단은 브라우저에 저장되어 정상 동작합니다. 백엔드는 로그인, 기기 간 진도 동기화, 협업 주석, 도입 현황(질문 집계)을 켭니다.

1
환경변수 
copy .env.example .env      # Mac·Linux: cp .env.example .env

.env 에 Supabase 대시보드의 VITE_SUPABASE_URL 과 VITE_SUPABASE_ANON_KEY 를 적습니다. anon key는 공개해도 되는 값이고 보안은 서버 규칙이 맡습니다. service_role 키는 절대 넣지 않습니다.

2
테이블 만들기

supabase/schema.sql 을 Supabase SQL 편집기에서 실행합니다. 이 단계는 프로젝트 소유자가 직접 합니다.

3
다시 빌드 
npm run deploy:build
npm run deploy:serve

환경변수는 빌드할 때 앱에 구워지므로, .env 를 바꾸면 반드시 다시 빌드합니다. 실제 서버에 올리는 절차는 docs/배포_가이드.md.

정본을 고쳤을 때

개념을 추가하거나 관계를 고치는 곳은 scripts/ontology/concepts.json 한 파일입니다. 그 뒤 세 단계면 아홉 소비처가 전부 따라옵니다.

npm run check:ontology                      # 1. 위치·앵커·순환 검사
npm run search:index && npm run ontology:graph   # 2. 산출물 두 개 재생성
# 3. 개발 서버는 새로고침, 조립본은 npm run deploy:build 로 다시 빌드
지키는 규칙 세 가지

개념 id 는 배포 뒤 바꾸거나 지우지 않습니다. 짝지을 실무 용어가 없는 비유어는 넣지 않습니다. 새 비유어를 챕터에 만들었으면 정본의 metaphors 에도 적어야 사전·튜터·검색이 함께 압니다.

12절

문제 해결

튜터가 다른 부 개념에 "이 시리즈에 없다"고 답합니다
개념 그래프 파일이 없는 것입니다. npm run ontology:graph 를 돌리고 새로고침하세요. 개발 서버라면 그 부의 web/public/concept-graph.json 이 생겼는지 봅니다.
챕터 상단에 띠가 안 보입니다
띠는 챕터 화면에만 있고 홈과 복습 목록에는 없습니다. 챕터인데도 없으면 위와 같이 그래프 파일 문제입니다.
띠의 다른 부 링크가 글자로만 보입니다
개발 서버(방식 B)에서는 정상입니다. 조립본(방식 A)에서 링크가 됩니다.
개념 지도에 진도나 다시 볼 개념 표시가 없습니다
조립본에서만 각 부의 진도를 읽습니다. 진단을 안 했으면 "다시 볼 개념"도 당연히 없습니다.
튜터 창에 "Ollama에 연결할 수 없어요"
Ollama 앱을 켜거나 ollama serve. 모델이 없으면 ollama pull gemma4:e2b. 확인은 curl http://localhost:11434/api/tags.
포트가 이미 사용 중이라고 합니다
조립본은 $env:PORT=4300; node scripts/serve-deploy.mjs 처럼 포트를 바꿔 띄웁니다. 개발 서버는 자동으로 다음 포트를 잡습니다.
npm install 끝에 산출물 두 줄이 안 보입니다
Node 버전이 낮으면 설치 후 스크립트가 실패합니다. Node 20 이상으로 올린 뒤 npm install 을 다시 하거나 npm run search:index, npm run ontology:graph 를 직접 돌립니다.
Jupyter에 "Python (MATH_PLATFORM)" 커널이 없습니다
3절 3단계의 마지막 명령(ipykernel install)을 다시 실행합니다. 튜터 창이 안 뜨면 그 커널에 %pip install ipywidgets 후 커널을 재시작합니다.
커밋이 막힙니다
훅이 출력한 항목을 고치면 됩니다. 온톨로지 검사 실패는 정본의 위치나 앵커가 실제 파일과 안 맞는 것이고, 대비 실패는 npm run check:contrast -- --fix 로 자동 수정할 수 있습니다.
