# 호스트 배포 가이드 (실사용 배포)

작성: 2026-07-16 · 대상: `deploy/` 조립본을 정적 호스트에 올려 실제 서비스하기.

> **끝 상태**: `https://…` URL 하나에서 포털(`/`)·전 11부(`/partN/`)가 뜨고, 로그인 시 진도·복습·진단이
> 기기 간 이어지는 상태. 관리자는 `/adoption`에서 도입 현황을 본다.
>
> 산출물은 이미 준비됨 — `npm run deploy:build`가 만드는 **`deploy/` 폴더가 자체 완결 정적 사이트**
> (SPA 폴백 `_redirects` 포함, Cloudflare Pages·Netlify 형식). `deploy/`는 gitignore(재생성물).

---

## ⚠️ 꼭 지킬 2가지 (안 지키면 조용히 깨짐)

1. **env는 빌드 타임에 박힌다** — `VITE_SUPABASE_URL`·`VITE_SUPABASE_ANON_KEY`가 **빌드하는 순간** 있어야
   JS에 구워진다(런타임 주입 아님). 호스트에서 빌드하면 그 빌드 환경에 값이 있어야 한다.
   각 앱 `vite.config`가 `envDir`로 **저장소 루트 `.env`**를 읽으므로, 루트에 `.env`가 있어야 한다.
   - anon key는 **공개 안전**(보안은 RLS·도메인 트리거). service_role 은 절대 넣지 말 것.
2. **한 origin(도메인 하나)** — 포털·전 부를 **같은 도메인**에 (포털 `/`, 부 `/partN/`). 서브도메인으로
   쪼개면 진도 2층(localStorage)·통합검색 크로스이동이 깨진다. `deploy/` 구조가 이미 이걸 보장한다.

---

## 방법 A — 로컬 빌드 + 드래그·업로드 (파일럿 최속, CI 불필요)

env가 이미 로컬 `.env`에 있으니 그대로 구워진다.

1. 루트에서 빌드:
   ```powershell
   npm run deploy:build      # deploy/ 생성 (VITE_SUPABASE_* 박힘)
   ```
2. `deploy/` 폴더를 업로드:
   - **Cloudflare Pages**: 대시보드 → Workers & Pages → Create → Pages → **Upload assets** → `deploy/` 드롭
   - **Netlify**: https://app.netlify.com → Sites → **`deploy/` 폴더 드래그**
3. 몇 초 뒤 `https://xxx.pages.dev` / `https://xxx.netlify.app` URL 생성. `_redirects` 자동 인식.

> 재배포: 코드 바뀌면 `npm run deploy:build` 다시 → 폴더 다시 업로드(같은 프로젝트에 덮어쓰기).

---

## 방법 B — GitHub 연결, push 시 자동 배포 (Cloudflare Pages 권장)

1. **Cloudflare Pages** → Create → Pages → **Connect to Git** → `math-platform` 선택(private 가능).
2. 빌드 설정:
   | 항목 | 값 |
   |---|---|
   | **Framework preset** | None |
   | **Build command** | 아래 한 줄 (env를 `.env`로 쓴 뒤 빌드) |
   | **Build output directory** | `deploy` |
   | **Root directory** | (비움 = 저장소 루트) |

   Build command:
   ```
   npm ci && printf 'VITE_SUPABASE_URL=%s\nVITE_SUPABASE_ANON_KEY=%s\n' "$VITE_SUPABASE_URL" "$VITE_SUPABASE_ANON_KEY" > .env && npm run deploy:build
   ```
3. **Environment variables** (Settings → Environment variables)에 입력:
   - `VITE_SUPABASE_URL` = `https://<프로젝트>.supabase.co`
   - `VITE_SUPABASE_ANON_KEY` = anon public key
   - Node 버전 문제 시 `NODE_VERSION` = `20`
4. Save & Deploy → 이후 `main`에 push하면 **자동 재빌드·배포**.

> Netlify도 동일: Build command 위와 같게, **Publish directory `deploy`**, Site settings → Environment 에 두 값.

---

## 방법 C — 사내 서버(nginx), 유출 0 엄격할 때

`deploy/`를 서버에 복사(예: `/var/www/deploy`) 후 nginx:
```nginx
server {
  listen 443 ssl;
  server_name learn.solideos.com;   # 예시
  root /var/www/deploy;

  location / { try_files $uri $uri/ /index.html; }              # 포털
  location /part1/  { try_files $uri $uri/ /part1/index.html; }
  location /part2/  { try_files $uri $uri/ /part2/index.html; }
  # … part3 ~ part11 동일 반복 …
  location /part11/ { try_files $uri $uri/ /part11/index.html; }
}
```
- 사내 인프라 + 원하면 Supabase self-host(Docker)까지 하면 데이터가 회사 밖으로 안 나간다.
- 빌드는 CI/로컬에서 하고 `deploy/`만 올리거나, 서버에서 `.env` 두고 `npm run deploy:build`.

## 배포 후 체크리스트

- [ ] **HTTPS** 로 접속되나 (Supabase·보안 컨텍스트 필수). Cloudflare/Netlify 자동, nginx면 인증서(Let's Encrypt 등).
- [ ] 배포 URL에서 **포털·아무 부**가 뜨고 새로고침해도 404 안 남(`_redirects`/try_files 동작).
- [ ] **로그인 → 진도 동기화** 동작(다른 브라우저에서 같은 계정 로그인 시 진도 이어짐).
- [ ] Supabase 콘솔: `Confirm email` OFF · `adoption_stats` 함수 배포됨(`supabase/schema.sql`).
- [ ] (선택) `/adoption`에서 도입 집계 뜨나.

> 경로 B(이메일+비밀번호)는 Supabase에 **별도 origin/redirect URL 설정이 불필요**하다. 나중에 매직링크로
> 바꾸면 그때 Auth → URL Configuration 에 배포 URL을 등록해야 한다.

---

## 로컬 사전 확인 (올리기 전 검증)

```powershell
npm run deploy:build
npm run deploy:serve      # http://localhost:4173 에서 조립본 그대로 확인
```
이 로컬 조립본에서 로그인·진도·검색이 되면, 같은 `deploy/`를 호스트에 올렸을 때도 동일하게 동작한다.

---

## 요약 한 줄
**`npm run deploy:build` → `deploy/` 폴더를 Cloudflare Pages/Netlify에 올리면 끝**(env는 빌드 시 박힘,
한 origin 유지). 파일럿은 방법 A(드래그), 자리 잡으면 방법 B(push 자동배포), 사내 엄격은 방법 C(nginx).
