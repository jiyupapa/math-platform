## ⚠️ 도입 조건 — 제품 완성 ≠ 실제 사용 (2026-07-09; 목표 변경 반영)

> 최우선 목표는 **"임직원이 실제로 쓰는 제품(도입)"**이다(위 목적 참조).
> 제품을 다 만들어도 임직원이 실제로 쓰기 시작하는 것은 **별개의 일**이다 — 완성은 필요조건이지 충분조건이 아니다.
> 해커톤은 목표가 아니라 **노출·피드백·초기 사용자 확보의 계기**로 활용한다.

**이미 강한 것 (유지):** 모트 실재(5부작+로컬 튜터) · [실측] 숫자(튜터 6초·₩0·오프라인, 170문항 자동채점, 8.5시간 완주) · **로컬·비용0·데이터 유출0** → 사내 도입 장벽이 원래 낮다.

**실제 도입을 가르는 변수 (중요도순):**

| # | 변수 | 왜 중요 | 대응 |
|---|---|---|---|
| 1 | 초기 사용자·실사용 증거 | 도입은 "쓰는 사람 1명"에서 시작. [설계] 숫자보다 완주한 동료 N명+후기가 확산을 부름 | 지금부터 동료 5~10명 파일럿 → 완주율·후기·이탈지점 |
| 2 | 도입 지점 | 자발적 확산은 드묾. 구체 도입 지점(신입 온보딩·AI 교육 등)이 있어야 붙음 | 도입 시나리오 1개 |
| 3 | 온보딩 마찰 | 임직원이 몇 분 안에 가치를 못 느끼면 이탈. 설치·접속·첫 화면 마찰 제거 | 배포 URL/QR, 로그인 없이 즉시 체험 |
| 4 | 지속 사용 고리 | 한 번 써보고 끝나지 않게 — 진도 저장·복귀 유인·경로 안내 | 진도·복습(기존) + 포털 "다음 목적지" 카드 |
| 5 | 실행 리스크(혼자·본업) | 제품·도입을 다 혼자. 완벽보다 "작동하는 최소 도입"부터 | ① 최소기능(진단 한 방) 우선·조기 배포 |
| 6 | 해커톤 = 수단 | 순위가 아니라 **노출·피드백·초기 사용자** 획득 창구로 활용. 데모는 "써보고 싶게" 만드는 데 집중 | QR 배포 + "지금 폰으로 열어보세요" |

**완성 → 도입 추가 작업 (제품 개발과 병행):**
- [ ] **실사용 파일럿** — 동료 5~10명에게 실제로 써보게 → 완주율·후기·이탈 지점 수집(제품 개선 입력 겸용).
- [ ] **배포 + 무마찰 온보딩** — 사내에서 URL/QR로 즉시 접속, 로그인 없이 첫 체험까지.
- [ ] **도입 지점 1개** — "○○본부 온보딩/AI 교육에 도입" 구체 시나리오.
- [ ] **데모를 '써보고 싶게'** — 진단→경로 재구성 한 방으로 "나도 해보고 싶다"를 유발(심사용이 아니라 사용자 유입용).

**확인 필요:**
- [ ] 첫 파일럿 대상 **동료 5~10명**을 지금 붙일 수 있나? (누구부터?)
- [ ] **구체 도입 지점**(온보딩 등)이 있나?
