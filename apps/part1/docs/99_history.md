### 🌙 다크 모드 — `dark:` 클래스 0개로 전 12앱 전환
앞선 색 토큰화가 깔아 둔 길 위에서 마무리. **마크업을 하나도 안 고쳤다.**

- **방식** — Tailwind v4 는 유틸리티를 `.bg-white{background-color:var(--color-white)}` 처럼
  변수 참조로 내보낸다. 그래서 `packages/ui/src/dark.css` 에서 팔레트 변수(`--color-*`)와
  데모 토큰(`--c-*`) 값만 다시 정의해 전 앱을 한 번에 뒤집었다(레이어 밖이라 @layer theme 를 이긴다).
  값은 손으로 적지 않고 `node_modules/tailwindcss/theme.css`(정본)에서 읽어 생성했다.
- **반전 규칙** — 강조색은 50↔950 · 100↔900 · 600↔400 · 700↔300(500 은 고정).
  중립(slate)은 공식이 아니라 **역할**로 짰다. 라이트의 밝기 사다리와 대비를 맞추는 게 목적이라
  400 은 500 으로만 내린다(양쪽 다 '장식용'): 라이트 slate-400/white ≈ 3.0:1 ↔ 다크 slate-500/slate-900 ≈ 3.4:1.
  표면은 페이지 slate-950 / 카드 slate-900 으로 벌려 카드가 사라지지 않게 했다.
  `--color-black` 은 안 뒤집는다 — 모바일 사이드바 오버레이 `bg-black/30` 은 다크에서도 어두워야 한다.
- **Chart.js** — canvas 는 CSS 변수를 못 읽는다. 자체 기본색(눈금·범례 `#666`)이 다크 카드 위에서
  **2.6:1** 이었다. `ChartView` 가 토큰에서 기본값을 만들어 깔고(사용자 옵션 우선), `themeVersion` 을
  구독해 테마가 바뀌면 다시 그린다 → 축 글자 **5.7:1**.
- **패키지의 plain CSS 3개도 토큰화** — `AuthPanel`·`NoteMarker`·`NotePanel` 에 hex 가 박혀 있어
  다크에서 흰 박스로 남았다. 20건 치환.
- **전환 UI** — `ThemeToggle`(시스템 → 라이트 → 다크 순환), 선택은 localStorage.
  첫 페인트 깜빡임은 각 `index.html` 인라인 스크립트가 막는다(번들보다 먼저 `data-theme` 적용).

**검증 — 라이트/다크 대비를 같은 페이지에서 자동 대조**했다(Tailwind 가 `oklch()` 로 내보내

### 🎨 데모 색 토큰화 — 하드코딩 hex 709곳 → `--c-*` 토큰 (다크 모드 선행 작업)
바로 앞 UI 정비에서 **다크 모드만 남겼던 이유**를 없앤 작업. 데모 컴포넌트에 hex 가 직접 박혀
있어서, 중립 램프를 뒤집어도 SVG 데모 64개의 축·격자는 밝은 색 그대로 남아 깨졌다.

- **실측으로 방식을 정했다** — SVG **표현 속성**에서 `var()` 가 동작하는지가 전제였다.
  Chrome 150 에서 `fill="var(--x)"`·`stroke="var(--x)"` 모두 계산값이 정확히 나오는 것을 확인하고 진행.
  (canvas 는 CSS 변수를 못 읽으므로 Chart.js 만 따로 처리 — 아래.)
- **`packages/ui/src/tokens.css` 신설** — `--c-*` 토큰 **52개**. **값은 하나도 바꾸지 않았다**(전부 기존 hex 그대로).
  이 작업의 목적은 색을 바꾸는 게 아니라 **한 곳에 모으는 것**이다. 이름은 Tailwind 팔레트를 그대로 따랐다.
- **치환 709건 / 97개 파일** — 팔레트 표에 있는 값만 바꾸는 방식이라, 본문 텍스트의 `#1000`·`#1001`
  (4부 토큰 ID 설명), `#FF0000`(9부 색상 표기 예시), `0xffff0000`(비트마스크)은 자동으로 안 건드렸다.
  SVG 이름색 `fill="white"` 3건도 토큰으로.
- **`ChartView` 에 토큰 해석기** — Chart.js 는 `<canvas>` 라 CSS 변수를 못 읽는다.
  `data`·`options` 를 훑어 `var(--c-*)` 를 `getComputedStyle` 로 실제 색으로 풀어 넘긴다.
  덕분에 챕터는 SVG 든 차트든 **같은 토큰 이름**을 쓴다.

**검증**: 전 12 워크스페이스 빌드 통과. 정의 토큰 52개 = 사용 토큰 52개(미정의 참조·미사용 정의 0).

(`packages/ui/src/base.css`)에 두고 12개 앱이 import 한다. Tailwind v4 는 유틸리티를
`@layer` 안에 넣으므로 레이어 밖의 이 규칙들이 마크업에 박힌 `text-xl`·`focus:outline-none`
같은 유틸리티를 이긴다 → **129개 챕터 파일을 건드리지 않고** 본문 리듬을 바꿀 수 있었다.

- **읽기 열 46rem 통일** — 컨테이너(`max-w-5xl`)는 그대로 두고 `article > *` 를 한 열로 묶어
  가운데 정렬. 이전엔 928px 에 한글 55~58자가 한 줄이었다(권장 35~40자). 문단만 좁히면
  설명의 절반이 담긴 `ConceptCard` 가 1272px 로 남아 **오히려 카드 안 문장이 길어져서**,
  문단·카드·문제를 한 열로 묶었다. 데모 SVG 는 고유 폭이 320~460px 라 이 열에서 안 잘린다.
  본문 17px — 대상이 수포자라 16px 는 조금 작다.
- **제목 위계** — `h2` 20px→24px + 위쪽 구분선. 같은 크기 카드가 20개씩 이어지는 챕터에서
  본문 대비 1.25배로는 절 경계가 안 보였다.
- **카드 계층 분리** (`ConceptCard`) — 설명(읽는 것)은 왼쪽 막대 + 옅은 배경, 문제/노트북(하는 것)은
  사방 테두리 상자. 이전엔 둘 다 `rounded-xl border p-5` 라 색조만 다른 같은 상자였다.
- **부 시각 정체성** — 11부에 고유색(1 sky · 2 blue · 3 cyan · 4 indigo · 5 violet · 6 amber ·
  7 teal · 8 purple · 9 orange · 10 pink · 11 fuchsia) + 사이드바 상단 색 띠 · 부 번호 칩.

  사이드바가 같은 언어로 읽힌다. 이전엔 11개 앱이 전부 indigo 라 위치 단서가 헤더 글자뿐이었다.
