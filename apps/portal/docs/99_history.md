### 🗺️ 학습 경로 지도 재구성 — 번호는 핵심 경로에만
위 점검의 4번(정보구조) 조치. 13개를 한 레일에 1..13 으로 늘어놓아 **"13단계 필수 코스"로 읽혔다** —
히어로의 "1→2→3→4→5 순서로 가지 않습니다 / 비선형 학습 경로" 와 지도가 서로 반대로 말하던 상태.
합계를 내보니 근거가 분명했다: **1~7 = 55챕터/37.4h**(히어로 칩 수치와 정확히 일치) vs
**8~13 = 63챕터/43.1h** — 선택분이 핵심보다 크다.

- **핵심 7단계**: 번호 배지 유지(`<ol>`), 머리말 "핵심 경로 · 7단계로 완주" 추가.
- **종료선**: "✓ 여기까지가 핵심 경로 — 55챕터 · 약 37시간" 으로 성격이 바뀌는 지점을 명시.
- **선택 6트랙**: `<ul>` + 점선 레일 + **번호 대신 역할 점**, "순서가 아니라 선택입니다 — 그래서 번호를
  붙이지 않았습니다" 문구. 점선은 `/map` 의 '선택 진입' 문법과 맞춘 것.
- **`step.order` 는 손대지 않았다** — `structure.ts` 의 진입조건 문구가 "1단계·2단계·4단계" 로 이 번호를
  참조하고 `?node=stepN` 딥링크·`S1~S13` 라벨도 여기 묶여 있다. 참조가 전부 핵심 1~7 이라 표시만 바꾸면
  안전하고, 전체 재번호였다면 문구 6곳 + 딥링크가 연쇄로 깨졌다.
- 곁들여 **제목 계층 교정**: 구획 머리말이 카드 제목과 같은 `h3` 라 부모가 아닌 형제로 읽히던 것을
  `H2 > H3(구획) > H4(카드)` 로 정리.
- 카드 마크업은 두 구획이 같은 `v-for` 를 돌아 **한 벌만 유지**(`sections` 계산 + `numbered` 로 레일만 분기).

**검증**: 진단 전/후 양쪽 실제 통과(진단 12문항을 UI 로 실제 응답 → 핵심 `필수`·선택 `선택` 배지 정상,
검증 후 `hub-diagnosis-v1` 삭제로 원상복구). 구조 실측 `OL 7개 전원 번호 · UL 6개 번호 0`,
제목 계층 `H1>H2>H3>H4×7>H3>H4×6`, 대비 실패 0건, 390px 오버플로 0. 전 12 워크스페이스 빌드 통과.

- **?node= 딥링크**: 노드 선택 ↔ URL 동기화(공유 가능), 상세 패널(분량·진도·진입 조건·

- **(사후 수정) 노드 클릭 시 화면이 맨 위로 튀던 문제** — 라우터 전역 `scrollBehavior`(top:0)가
