### 🌙 다크 모드 — `dark:` 클래스 0개로 전 12앱 전환
앞선 색 토큰화가 깔아 둔 길 위에서 마무리. **마크업을 하나도 안 고쳤다.**

- **방식** — Tailwind v4 는 유틸리티를 `.bg-white{background-color:var(--color-white)}` 처럼
  변수 참조로 내보낸다. 그래서 `packages/ui/src/dark.css` 에서 팔레트 변수(`--color-*`)와
  데모 토큰(`--c-*`) 값만 다시 정의해 전 앱을 한 번에 뒤집었다(레이어 밖이라 @layer theme 를 이긴다).
  값은 손으로 적지 않고 `node_modules/tailwindcss/theme.css`(정본)에서 읽어 생성했다.
- **반전 규칙** — 강조색은 50↔950 · 100↔900 · 600↔400 · 700↔300(500 은 고정).
  중립(slate)은 공식이 아니라 **역할**로 짰다. 라이트의 밝기 사다리와 대비를 맞추는 게 목적이라
  400 은 500 으로만 내린다(양쪽 다 '장식용'): 라이트 slate-400/white ≈ 3.0:1 ↔ 다크 slate-500/slate-900 ≈ 3.4:1.

### 🎨 데모 색 토큰화 — 하드코딩 hex 709곳 → `--c-*` 토큰 (다크 모드 선행 작업)
바로 앞 UI 정비에서 **다크 모드만 남겼던 이유**를 없앤 작업. 데모 컴포넌트에 hex 가 직접 박혀
있어서, 중립 램프를 뒤집어도 SVG 데모 64개의 축·격자는 밝은 색 그대로 남아 깨졌다.

- **실측으로 방식을 정했다** — SVG **표현 속성**에서 `var()` 가 동작하는지가 전제였다.
  Chrome 150 에서 `fill="var(--x)"`·`stroke="var(--x)"` 모두 계산값이 정확히 나오는 것을 확인하고 진행.
  (canvas 는 CSS 변수를 못 읽으므로 Chart.js 만 따로 처리 — 아래.)
- **`packages/ui/src/tokens.css` 신설** — `--c-*` 토큰 **52개**. **값은 하나도 바꾸지 않았다**(전부 기존 hex 그대로).
  이 작업의 목적은 색을 바꾸는 게 아니라 **한 곳에 모으는 것**이다. 이름은 Tailwind 팔레트를 그대로 따랐다.
- **치환 709건 / 97개 파일** — 팔레트 표에 있는 값만 바꾸는 방식이라, 본문 텍스트의 `#1000`·`#1001`
  (4부 토큰 ID 설명), `#FF0000`(9부 색상 표기 예시), `0xffff0000`(비트마스크)은 자동으로 안 건드렸다.
  SVG 이름색 `fill="white"` 3건도 토큰으로.
- **`ChartView` 에 토큰 해석기** — Chart.js 는 `<canvas>` 라 CSS 변수를 못 읽는다.
  `data`·`options` 를 훑어 `var(--c-*)` 를 `getComputedStyle` 로 실제 색으로 풀어 넘긴다.
  덕분에 챕터는 SVG 든 차트든 **같은 토큰 이름**을 쓴다.

**검증**: 전 12 워크스페이스 빌드 통과. 정의 토큰 52개 = 사용 토큰 52개(미정의 참조·미사용 정의 0).

- **실험(ScoreFlipLab)**: 진짜 실력을 미리 정한 두 모델(A 72% vs B 70%)에게 문항 수
  25~5,000짜리 벤치마크를 20회씩 — 50문항에선 실력이 낮은 **B가 이긴 시험 10번+동점 1**
  (사실상 동전 던지기), 1,000문항부터 0번. 기본 화면(50문항 1회차)은 A 70 vs B 76 **역전
  상태로 시작**. ±오차범위 밴드 토글(여론조사 ±3.1%p 예고, 공식은 6장).

  포함), 용어 3(벤치마크=모의고사·표본=국자·오차범위=여론조사의 ±), 더 깊이(√n — 3부 7장 회수),
