## 프로젝트 정체성

"수포자를 위한 AI 수학 시리즈"의 **11부 — 에이전트와 추론의 수학**. **실용·전략 트랙** —
"AI가 글을 쓴다"(4부)를 넘어 "**AI에게 일을 맡긴다**": 다단계 과업의 성공률(확률의 곱),
재시도/Best-of-N(기하분포), self-consistency 다수결(이항), 검수자와 베이즈, 추론 시점 컴퓨트
(test-time compute)·탐색·멀티에이전트·컨텍스트 예산·pass@k 를 한 서사로 묶어,
"에이전트에게 이 업무를 맡겨도 되나"에 **계산으로 답하는 눈**을 기른다.
도달점은 **12장(캡스톤 — 이 에이전트, 도입해도 되나)**: 가상 에이전트 제품 자료를 읽고
① 과업 사슬 성공률을 검산하고 ② pass@k·검수 설계를 해석하고 ③ 비용 대 정확도로 도입 결론을
내는 상태. **3부 4장(조건부 확률·베이즈)의 정면 회수처**이자 10부(평가 통계)의 속편.
사내 도입 서사 직결 — "에이전트에게 일을 맡겨도 되나요? 검수는 몇 번?"에 계산으로 답하는
에이전트 리터러시.
핵심 한 줄: **"일의 성공률은 걸음의 곱이고, 되살리는 길은 다시 뽑기·다수결·검수다."**

> **상태: ✅ 완결 (2026-07-13) — 전 13챕터(워밍업 + 1~12장) 공개. 착수부터 당일 완주.**
> 챕터 구성·회수하는 수학 매핑은 루트 `README.md` "11부 챕터 구성" 표가 정본.
> 진행 상태 추적은 `docs/00_plan.md`.

## 콘텐츠 작성 규칙 (필수 — 대상이 수포자임)

1. 직관 먼저, 공식 나중 — 그림/비유 → 인터랙티브 조작 → 수식.
2. 새 용어·기호·수식은 예외 없이 즉시 설명("이름 + 읽는 법 + 뜻").
   **비유어를 만들면 같은 자리에서 실무 용어와 짝지을 것** — 이 부의 비유 체계(일꾼/징검다리):
   AI 일꾼=에이전트(agent)·징검다리=과업 사슬(task chain)·제비 다시 뽑기=Best-of-N(best-of-N
   sampling)·다수결 회의=자기 일관성(self-consistency)·검수자=검증자(verifier)·
   생각의 길이=추론 시점 컴퓨트(test-time compute)·갈림길 지도=탐색 트리(search tree)·
   책상 위 서류 더미=컨텍스트 윈도(context window)·k번 안에 한 번=pass@k.
3. **"회수하는 수학" 연결 필수** — 각 장이 어느 부의 어느 개념을 회수하는지(루트 README 표)
   `ConceptCard` 로 명시: 워밍업·2장=3부 3장(독립 곱), 3장=3부 4장(조건부), 4장=3부 5장(분포)·
   10부 6장(±), 5장=3부 5·7장(이항·큰 수), **6장=3부 4장(조건부·베이즈) 정면 회수**·6부 4장(판별),
   7장=10부 2·4장(멱법칙·예산)·9부 1장(비용), 8장=4부 12장(후보 고르기)·2부 7장(지수),
   9장=10부 9장(심판·선수 분리)·3부 10장(상관), 10장=5부 1~2장(정보·압축)·7부 8장(RAG),
   11장=10부 6·7장(±·쌍대)·3부 8장(추정), 12장=전 시리즈.
   ⚠️ 부 간 링크 전 **해당 부 `chapters.ts` 실물로 장 번호를 재확인**할 것 — 문서 구표기와
   실제 목차가 어긋난 사례 있음(예: 빔 서치는 4부 12장에 없다 — 8장이 자체 소개).
4. 문제 표준: 본문 미니체크 2~3개 + 챕터 끝 10문제 `QuizSet`(완료 시 진도 처리). 계산형은 `StepQuiz`.
5. 웹 챕터 ↔ 노트북 1:1, 같은 예제.
6. **실습은 전부 오프라인·결정적** — 시드 고정(mulberry32, 웹·노트북 동일 난수열) 가상 과업 사슬
   시뮬, 검수자·투표·탐색 시뮬. 실제 에이전트 프레임워크·외부 API 호출을 요구하지 말 것.
   에이전트 제품·도구명은 **가상의 이름**(실존 제품 비방/오인 방지) — 단 수학은 실제 관행
   (pass@k 정의, Best-of-N, self-consistency 다수결, 베이즈 검수)과 일치.
7. 부 간 참조 링크는 "지정석"(AI 연결 카드·완주 박스)에만 `PartLink` 사용, 본문 인라인은 텍스트.
8. **시리즈 질문 사슬 유지** — 6부 "무엇을 배우게 할까" · 8부 "어떻게 잘" · 9부 "무엇으로 담나" ·
   10부 "얼마나 키우고, 정말 좋아졌나" · 11부 "**이제 일을 맡겨도 되나**" — 부려 쓰는 단계의 수학.
9. **분량 방침: 줄이지 않는다** — 장 병합·주제 삭제 금지, 자세한 설명을 위한 확장은 환영
   (메모리 `content-depth-over-brevity`).

## 자주 막히는 함정

- **확률 심화(3부 4~5장)를 안 본 학습자도 막히면 안 된다** — 조건부 확률·분포는 처음 보는
  학습자를 위한 최소 직관을 자체 포함(10부가 신뢰구간을 자체 포함했던 방식). 단, 3부에서
  배웠다면 "그때 그 공식"으로 회수를 명시.
- **수치는 전부 사전 검증된 결정적 toy 예제** — 사슬 성공률·기하/이항 계산·베이즈 사후확률·
  pass@k 등 본문 수치는 노트북 assert 로 고정하고 웹 시뮬과 일치시킬 것(10부 전례).
- **상관된 오류를 정직하게** — 다수결(5장)·멀티에이전트(9장)의 이득은 오류 독립 가정에서만
  성립. 같은 모델의 답은 상관되므로 이론 상한과 실제의 차이를 반드시 명시(10부 9장 "일치하는
  오심"과 같은 철학).
- 챕터 라우트를 `router/index.ts` 에 등록하지 않으면 catch-all 이 ComingSoonView 로 보낸다.
- Tailwind `@source`(style.css)가 빠지면 공용 컴포넌트 스타일이 조용히 사라진다 — 빌드는 통과하므로 눈으로 확인.
- KaTeX 백슬래시: 정적 `expr="..."` 는 1개, JS 바인딩(StepQuiz steps 등)은 2개.
